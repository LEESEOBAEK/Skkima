# 쓰끼마 데스크톱 정보 구조 개선 명세

## 1. 목적

기존 Schema Workflow 데이터 계약과 데스크톱 기능을 유지하면서 사용자가
작업의 현재 상태, 진행 이유, 산출물, 검토 근거와 다음 행동을 한 화면에서
추적할 수 있도록 정보 구조를 정리한다.

## 2. 확정된 설계 원칙

1. 전체 구조를 먼저 고정하고 화면은 단계적으로 개선한다.
2. 메인 화면은 상단 운영 요약과 시간순 작업 흐름을 함께 사용한다.
3. 상세 정보는 선택할 때만 오른쪽 검사 패널에 표시한다.
4. 사용자는 프로젝트와 작업 세션을 중심으로 탐색한다.
5. Run ID와 Operation ID는 기본 화면에서 강조하지 않고 상세 패널에서 제공한다.
6. 기존 Workflow manifest와 프로젝트 계약은 변경하지 않는다.
7. 원본 데이터는 읽기 전용이며 화면에서 사용하는 이름과 보기 상태만 로컬에 저장한다.
8. 작은 창에서는 상세 패널을 덮개형 화면으로 전환한다.

## 3. 화면 구조

```text
프로젝트/작업 세션 | 작업 제목과 운영 요약 | 선택형 상세 패널
                   | 작업 흐름
                   | 검토
                   | 산출물
                   | 이력
```

### 상단 운영 요약

- 상태
- 검증
- 산출물 수
- 다음 행동

### 시간순 작업 흐름

- 최초 요청
- 이어가기 요청
- 산출물 등록
- Workflow 결과

### 상세 패널

- 요약: 상태, 검증, 다음 행동과 품질 판단 근거
- 실행: Run ID, Operation ID, Session reference와 관계
- 산출물: 경로, 역할, 크기, 생성 시각
- 작업: 프로젝트 폴더, 작업 세션과 저장 범위

## 4. 상호작용 규칙

1. 운영 요약, 작업 흐름 항목, 산출물 행을 선택하면 상세 패널을 연다.
2. 패널을 닫으면 메인 작업 흐름이 전체 너비를 사용한다.
3. 패널 너비는 사용자가 조절할 수 있고 로컬에 저장한다.
4. 작업 세션별로 마지막으로 본 상세 항목을 기억한다.
5. 좁은 화면에서는 패널이 오른쪽에서 겹쳐 표시되며 닫기 버튼을 항상 제공한다.
6. 설정, 아카이브, 로컬 환경처럼 앱 전체 범위의 화면은 기존 대화상자를 유지한다.

## 5. 이번 구현 범위

- 상단 운영 요약 추가
- 기존 동반 패널을 선택형 상세 검사 패널로 교체
- 작업 정보와 실행 정보를 상세 패널로 통합
- 산출물과 시간순 활동에서 상세 패널 연결
- 패널 너비 조절과 반응형 동작
- UI 계약 및 읽기 모델 회귀 테스트

## 6. 제외 범위

- Workflow manifest 스키마 변경
- 프로젝트와 Run의 실제 폴더 이동
- 파일 편집 및 Workflow 실행
- React 또는 Astryx 라이브러리로 프런트엔드 교체
- 프로젝트 → 작업 세션 → Run 저장 모델의 마이그레이션

## 7. 완료 기준

- 기존 테스트가 모두 통과한다.
- 상태, 검증, 산출물 수와 다음 행동을 상단에서 확인할 수 있다.
- 작업 정보, 실행 정보와 산출물 정보가 동일한 상세 패널에서 열린다.
- 상세 패널을 닫아도 현재 작업과 탭 선택이 유지된다.
- 1150px 이상에서는 분할 패널, 그 미만에서는 덮개형 패널로 동작한다.
- 긴 경로와 식별자가 화면 밖으로 밀어내지 않는다.
