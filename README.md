# Skkima (쓰끼마)

> AI CLI 작업을 프로젝트 단위로 관리하고, 실행 과정과 산출물을 검증 가능한 결과로 연결하는 Windows 데스크톱 포트폴리오 프로젝트

## 프로젝트 소개

나는 쓰끼마를 완성된 상용 제품으로 공개하기보다, AI CLI를 활용한 작업이 여러 프로젝트와 터미널에 흩어지면서 발생하는 상태 추적, 결과 검토, 실행 복구의 어려움을 해결하기 위해 설계한 Windows 데스크톱 포트폴리오 프로젝트로 소개하고 싶다.

쓰끼마는 프로젝트, 작업 세션, AI CLI 실행, 실행 상태, 근거, 산출물을 하나의 흐름으로 연결한다. AI가 작업을 완료했다고 보고하는 것과 실제 결과를 사람이 검토하고 확인하는 과정을 분리하여, 현재 상태와 다음 행동을 더 명확하게 파악할 수 있도록 구성했다.

## 핵심 사용 흐름

```text
프로젝트 생성
→ 작업 세션 시작
→ AI CLI 선택 및 실행
→ 실행 상태와 Run 정보 확인
→ 산출물·근거·검증 결과 검토
→ 실행 완료 또는 중단·복구
→ 프로젝트 기록으로 보존
```

## 해결하려는 문제

AI CLI를 직접 사용하면 프로젝트 경로, 작업 세션, 실행 상태, 산출물과 검토 결과가 서로 다른 위치에 남기 쉽다. 작업이 성공했다는 보고만으로는 실제 산출물의 존재와 검증 여부를 한눈에 확인하기 어렵고, 실행이 중단되거나 실패했을 때 어떤 상태로 복구해야 하는지도 불명확해질 수 있다.

쓰끼마는 이 문제를 프로젝트와 작업 세션을 기준으로 구조화하고, 실행 기록과 산출물을 연결하며, 검증 결과와 다음 행동을 함께 보여주는 방식으로 해결한다.

## 공개 범위

이 저장소는 개인 로컬 환경에서 검증한 기능과 설계 결과를 선별한 포트폴리오 공개판이다. 전체 운영 데이터나 내부 실험 과정의 복제본이 아니라, 문제 정의, 설계, 구현 판단, 검증 결과를 이해하기 위한 공개 스냅샷으로 관리한다.

공개하지 않는 항목은 다음과 같다.

- 실제 사용자 작업 데이터와 실행 로그
- 개인 경로, 계정 정보, API 키와 로그인 정보
- `node_modules`와 Rust `target`
- 검증되지 않은 성능 수치
- 미완성 실험 코드와 내부 운영 설정

## 현재 범위와 제한사항

- Windows 11 개인 로컬 환경을 기준으로 한다.
- Codex, Claude Code, Antigravity 연동을 중심으로 설명한다.
- 다중 사용자 협업, 원격 데이터 동기화, 다른 운영체제는 보장하지 않는다.
- 브라우저 자동화와 외부 연결 기능은 검증 범위에 따라 실험 기능으로 표시한다.
- 공개판은 완전한 상용 배포 제품이 아니며, 운영용 구현은 별도 개발 저장소에서 관리한다.
