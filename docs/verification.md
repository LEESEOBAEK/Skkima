# 검증 원칙과 결과

쓰끼마는 화면이 열리는지보다 프로젝트에서 결과 검토까지 이어지는지를 검증 대상으로 삼는다.

## 최신 검증 결과

검증 기준 버전은 데스크톱 앱 0.1.5다.

| 검증 항목 | 결과 |
|---|---|
| JavaScript 테스트 | 138건 통과 |
| Rust 테스트 | 91건 통과 |
| 네트워크 의존 Rust 테스트 | 2건 제외 |
| Rust 포맷 검사 | 통과 |
| Tauri 릴리스 빌드 | 통과 |
| Windows NSIS 패키지 | 통과 |
| 한국어 포함 Codex 프롬프트 | Windows 실행 경로 수정 후 재검증 대상 |

## 검증 영역

- 프로젝트·작업 세션·Run 관계
- 새 작업·이어가기·분기 준비
- Codex·Claude Code·Antigravity 실행 경계
- CLI 중단·복구와 interrupted 상태 표시
- Run ID·검증 결과·산출물·다음 행동 표시
- 프로젝트와 세션의 아카이브·복원
- 로컬 스킬과 GitHub 저장소 기반 플러그인 등록
- 브라우저 읽기 근거와 명시적 클릭 승인
- Windows 설치·재설치·제거
- 공개 패키지의 개인 경로·비밀값·실행 데이터 제외

## 검증 방식

1. Rust와 JavaScript의 단위·계약 테스트를 실행한다.
2. Tauri 릴리스 빌드와 Windows NSIS 패키지 생성을 확인한다.
3. 빈 프로젝트, 완료 Run, 실패 Run, 중단 Run을 각각 확인한다.
4. 대표 화면에서 상태·산출물·다음 행동이 일치하는지 수동 확인한다.
5. 개인 데이터와 환경 의존 문구가 공개 자산에 남지 않았는지 확인한다.

## 해석 원칙

- 테스트 통과는 해당 계약과 동작을 검증했다는 뜻이지 모든 Windows 환경을 보장한다는 뜻이 아니다.
- 브라우저와 외부 연결은 사이트별 로그인·구조 차이가 있으므로 제한된 검증으로 표시한다.
- 실제 성능 수치와 다중 사용자 운영 수준은 이 포트폴리오의 검증 범위가 아니다.
- 확인되지 않은 동작은 제한사항 또는 후속 검증 대상으로 남긴다.
