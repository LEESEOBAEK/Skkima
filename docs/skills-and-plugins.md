# 스킬과 플러그인 관리

쓰끼마의 확장 기능은 Workflow Engine 계약과 분리된 라이브러리로 관리한다. 따라서 스킬을 추가하는 일과 특정 프로젝트에서 스킬을 설치해 사용하는 일은 서로 다른 단계다.

## 관리 단위

| 단위 | 역할 |
|---|---|
| 스킬 원본 | 로컬 skill 문서 또는 공개 GitHub 저장소에서 가져온 원본 |
| 라이브러리 스냅샷 | 원본의 revision과 snapshot hash를 기록한 재사용 가능한 사본 |
| 프로젝트 설치 | 선택한 프로젝트 내부에 설치하고 플랫폼별 인식 상태를 확인 |
| 실행 기록 | 어떤 스킬을 사용했는지와 결과를 Workflow Run에서 추적 |

## 현재 공개 범위

- 로컬 스킬 파일 등록
- 공개 GitHub 저장소의 여러 스킬 검색
- 필요한 스킬만 선택적으로 프로젝트에 등록
- Codex·Claude Code·Antigravity 호환 상태 표시
- 프로젝트 설치 상태와 라이브러리 원본을 분리

## 안전 경계

- 저장소를 가져왔다고 해서 모든 스킬을 자동 설치하지 않는다.
- 원본 revision과 snapshot hash를 기록한다.
- 프로젝트별 설치 여부를 확인한 뒤 CLI에서 사용한다.
- 스킬 문서가 있다고 해서 그 내용의 업무 규칙이나 외부 서비스 권한을 자동 승인하지 않는다.
- 미검증 스킬은 포트폴리오에서 지원 기능으로 과장하지 않는다.

이 구조는 Codex나 다른 AI 도구의 확장 기능을 그대로 복제하기 위한 것이 아니라, 쓰끼마의 프로젝트 기록과 연결해 설치·호환·사용 범위를 추적하기 위한 것이다.
