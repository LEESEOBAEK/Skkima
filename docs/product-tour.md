# 사용 흐름

## 1. 프로젝트를 연다

실제 Windows 프로젝트 폴더를 선택하면 쓰끼마가 해당 폴더의 계약 파일과 Workflow Run 기록을 읽는다. 앱 내부에 작업물을 복제하지 않기 때문에 원본 프로젝트와 실행 기록의 위치를 추적할 수 있다.

## 2. 작업 세션을 선택한다

프로젝트 안의 작업 세션은 새 작업, 기존 Run 이어가기, 기존 Run 분기로 구분한다. 이어가기와 분기는 기준 Run이 유효한지 확인한 뒤에만 준비한다.

## 3. 실행을 준비한다

준비된 Run에서 작업 관계, 실행 플랫폼, 승인 방식과 현재 상황을 확인한다. 이 단계에서는 사용자가 어떤 CLI를 사용할지 선택하고 실행 전 조건을 확인한다.

## 4. CLI를 실행한다

Codex, Claude Code, Antigravity 중 설치된 CLI를 선택하면 별도 PowerShell 창에서 실행한다. 앱은 실행 상태와 로그 경로를 기록하고, 원본 산출물을 임의로 편집하지 않는다.

## 5. 결과를 검토한다

작업 화면에서 상태, 검증, 산출물 수, 다음 행동을 먼저 보고 필요한 경우 실행 정보에서 Run ID와 Operation ID를 확인한다. 근거 부족이나 검토 필요 상태는 완료와 구분한다.

## 6. 중단과 복구를 확인한다

실행 중단은 명시적 승인 후 수행한다. 중단된 CLI는 기록을 지우지 않고 aborted 상태로 남기며, Workflow가 아직 실행 가능한 경우 재시작 경로를 제공한다.

## 포트폴리오 시연 순서

1. 빈 작업 공간 화면
2. 프로젝트 폴더 열기
3. 작업 세션 생성 또는 선택
4. 준비된 Run과 실행 정보 확인
5. 결과 산출물과 검증 상태 확인
6. 중단·복구 또는 아카이브 흐름 설명

이 순서는 기능을 나열하는 대신 문제에서 결과까지의 사용 맥락을 보여주기 위한 구성이다.
