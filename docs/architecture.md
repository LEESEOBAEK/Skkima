# 구조와 책임 경계

쓰끼마는 Windows 데스크톱 인터페이스와 Python Workflow Engine, AI CLI를 연결하지만 각 영역의 책임은 분리한다.

~~~text
사용자
  ↓
Tauri 데스크톱 앱
  ├─ 프로젝트와 작업 세션 탐색
  ├─ 실행 준비·승인·상태 표시
  └─ 산출물·근거·검증 결과 검토
       ↓
Rust 로컬 경계
  ├─ Windows 폴더와 프로세스 접근
  ├─ CLI 실행·중단·복구
  ├─ 로컬 상태 저장
  └─ 민감 정보의 공개 범위 제한
       ↓
AI CLI와 Python Workflow Engine
  ├─ 요청 구조화
  ├─ independent·continuation·branch 관계 관리
  ├─ fulfillment와 산출물 등록 검증
  └─ 프로젝트 내부 기록 생성
~~~

## 주요 구성

| 구성 | 책임 | 포트폴리오에서 확인할 점 |
|---|---|---|
| 데스크톱 UI | 프로젝트·세션·Run을 탐색하고 결과를 표시 | 운영 흐름을 한 화면에서 이해 |
| Tauri·Rust | Windows 기능과 프로세스 실행의 경계 | CLI를 무분별하게 직접 실행하지 않음 |
| AI CLI | 선택된 도구로 실제 작업 수행 | Codex·Claude Code·Antigravity를 선택적으로 사용 |
| Workflow Engine | 요청·관계·완료 조건·산출물 등록 검증 | 보고와 검증을 분리 |
| Research Preflight | 출처 메타데이터, 프로젝트 내부 파일 경로, 근거 수를 실행 전에 검증 | 근거 부족·변경된 자료로 CLI가 시작되지 않음 |
| 프로젝트 데이터 | Run 기록·근거·산출물 경로 보존 | 원본 프로젝트 안에서 추적 가능 |

## 중요한 경계

- 쓰끼마는 AI가 만든 결과를 대신 승인하지 않는다.
- 완료 보고, 검증 결과, 사람의 후속 행동을 서로 다른 정보로 표시한다.
- 원본 산출물은 앱이 임의로 수정하지 않는다.
- 프로젝트 기록은 기본적으로 사용자 PC에 보관한다.
- CLI별 옵션 차이는 실행 경계에서 처리한다.
- 리서치 원문은 프로젝트에 보관하고, Run에는 출처의 참조와 검증 결과만 연결한다.
- 웹 수집·로그인·자동 다운로드는 제품 책임 범위에 포함하지 않는다.
- 공개 저장소에는 실제 작업 데이터와 개인 경로를 포함하지 않는다.

## 상태 흐름

~~~text
프로젝트 선택
  → 작업 유형 확인
  → Prepared Workflow Run 확인
  → 사용자 승인
  → CLI 실행
  → 실행 중·완료·실패·중단
  → 산출물과 검증 결과 확인
  → 재시작 또는 기록 보존
~~~

이 구조의 목적은 복잡한 자동화를 무조건 실행하는 것이 아니라, 현재 작업의 위치와 다음 행동을 잃지 않게 하는 것이다.
